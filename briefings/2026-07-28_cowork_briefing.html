Cowork Briefing

Week of July 28, 2026 · Window July 14–28 (extended for hands-on research) · hands-on-first

Briefing summary

Cowork learns three new ways to take on work: watching, reading live, listening

Within two weeks, Cowork gains three new ways to hand off work: a screen recording instead of a typed instruction, a dashboard with live instead of frozen data, a voice mode that can now talk to connected tools. All three require watching or listening first, then explicit approval.

The hands-on side stays narrow but unusually concrete: two independent first tests of the same brand-new feature land with a real before-and-after right in this window — honestly assessed below rather than hyped up.

What shipped this week

Cowork / Feature July 21, 2026

"Record a Skill": Cowork builds automations from a narrated screen recording instead of prompts

On July 21, Anthropic released "Record a Skill" in Cowork: instead of writing instructions, you record your own screen once, narrating the reasoning behind each step out loud, and Claude turns that into a reusable skill callable via a slash command. The feature sits in the "+" menu of a Cowork session in the Claude desktop app and is limited to Pro, Max, and Team plans — the free plan is left out, and web and mobile don't have it.

That makes five ways to build a skill now: write it by hand, have Claude generate it from a description, retroactively package an already-completed Cowork session, upload a finished package — and now, simply demonstrate it. Recording is the only way that involves no writing at all.

Read more

Context & background. Anthropic arrives exactly 33 days after OpenAI: Codex's "Record & Replay" in the Codex desktop app had already been running since June 18. Two frontier labs placing the same bet in the same product cycle — automation through demonstration rather than description — is, according to Digital Applied, a signal of where office automation as a whole is heading.

The details. Head to head, the two implementations differ exactly where it matters for real-world use. Reach: Claude's version runs on Windows and macOS with no stated regional exclusions, while Codex is a macOS-only build and is blocked in the EEA, the UK, and Switzerland. Transparency runs the other way: OpenAI has documented that its recorder stores a demonstration as semantic intent JSON rather than pixel coordinates — the stated reason replays are supposed to survive small UI changes; Anthropic has published nothing about its own internal representation. Codex hard-caps a recording at 30 minutes; no limit is stated for Cowork. On the governance side, Anthropic's state is, in Digital Applied's assessment, "thin": no dedicated help page on retention, editing, or admin controls at launch — for now, anyone recording has to rely on Cowork's general security documentation, which even before "Record a Skill" warned that visible screen content can contain private data.

Context for your stack. The most obvious rule of thumb from the hands-on coverage: tasks that can be fully narrated out loud in one pass (pulling reports, normalizing tables, classifying entries) are a good fit; exception handling, pricing or contract decisions, and anything involving credentials or personal data belong on the do-not-record list. For any automation of your own: the recording is a specification, not proof — it shows exactly one successful path through the task, not error handling.

Watch items. (a) A user comment under one of the hands-on reports linked below reported on July 23 that the feature only worked on Mac for them, not Windows — a possible contradiction of the officially stated Windows support, most plausibly explained by a staggered rather than simultaneous rollout. (b) Whether Anthropic delivers the missing governance documentation (retention, editing, per-seat admin controls) in the near term. (c) Whether Anthropic, like Codex, discloses how a recording is represented internally — this determines whether recorded skills survive UI changes in the target application.

Substrate / Claude Code July 13–17, 2026, picked up July 24

Claude Code Artifacts pull live data via MCP connectors — but a connector-bound dashboard can't be a public link on any plan

Twenty-five days after the beta launch on June 18, an update window (Claude Code versions 2.1.207 through 2.1.212) catches up on three things at once: a published Artifact page can now pull fresh data via MCP connectors on every visit instead of showing only a snapshot from build time; public share links are added; and on Team/Enterprise plans, multiple people can keep building on the same page together. Connector calls require at least Claude Code 2.1.209; the page size ceiling remains unchanged at 16 MiB of rendered content.

The catch that, according to Digital Applied, hardly any coverage puts front and center: an Artifact page that calls connectors cannot be shared as a public link on any plan. Live data and a no-login link are mutually exclusive on the same page.

Read more

Context & background. Before this update, an Artifact page was either shareable only within an organization or not shareable at all, and every page was a frozen snapshot of the build session — Digital Applied had already named both limitations as hard constraints in its June guide to the beta launch.

The details. Architecturally, connector calls run through the viewer's own connections, not the publisher's — two people opening the same dashboard can see different data depending on their own access, and the page itself never gets to see credentials. On Pro/Max, a public link is the only sharing route at all; on Team/Enterprise, sharing defaults to organization-internal — which means a connector-bound dashboard on Pro/Max is necessarily stuck private with its author. On the governance side, the feature set is unusually complete for a feature this young: separate on/off switches for Artifacts overall and for connector calls specifically, separate retention periods for private vs. shared Artifacts, an audit log event type for every publish/share/delete action, and a compliance API for programmatically listing and deleting them.

Context for your stack. For the Webzeitung pipeline itself, this is no direct substitute — the no-JavaScript and public-access rule that applies there sits exactly in the gap this feature leaves open: a self-updating dashboard open to everyone can't be built this way, but an organization-internal one for personal use (say, a private tracking dashboard over connected tools) can, without writing a line of code.

Watch items. Whether the live-data/public-link exclusivity — in Digital Applied's own assessment, the most likely of the current hard limits to fall — gets lifted in one of the next updates, given the pace from beta to a fully built-out governance feature set in just 25 days.

Cowork / Voice Mode July 23, 2026

Voice mode leaves its Haiku-only phase: Opus and Sonnet can now be addressed, complete with Gmail, calendar, and Slack access

Fourteen months after its original launch, Anthropic freed voice mode from its Haiku-only restriction on July 23: paying plans can now switch between Claude Opus, Sonnet, and Haiku mid-conversation, and spoken requests can reach connected tools — Anthropic's own help page names Gmail, Google Calendar, Google Docs, and Slack specifically, and press coverage additionally shows Canva and Notion in examples. Before any action on a connected tool, Claude asks explicitly for permission, just as in text mode.

Voice mode deliberately remains turn-based — Claude listens, pauses to think, then responds — unlike OpenAI's "GPT-Live," brought to the desktop the same day, which can listen and speak at the same time. Also excluded is Claude Fable, Anthropic's strongest model: voice mode now reaches the strong models, but not the strongest one.

Read more

Context & background. Voice mode actually launched in beta back in May 2025 and ran on Claude Sonnet 4 at the time, not Haiku — at some point between then and 2026, Anthropic switched to Haiku-only for cost and latency reasons. The July 23 move is thus more of a reclaiming than a first launch: voice mode is catching up to the model quality that text users have long been used to.

The details. The default is telling: voice mode starts with whichever model was last used in text chat and runs its fastest variant, so the conversation stays real-time — Anthropic doesn't ask you to trade off speed against intelligence per answer, but instead automatically routes to the fastest version of the model you already prefer. Voice conversations also count against the same usage limit as text chat; there's no separate voice quota. Language support covers roughly ten languages across eleven region options (the discrepancy comes from Spanish being counted as one language but two regions); non-English remains in beta and must be selected manually.

Context for your stack. The practical catch isn't the feature itself but its maturity: for read-only tasks — checking a calendar, summarizing an email thread — the current state is already usable; for write actions via voice (updating a CRM, actually sending an email), the approval gate does exist, but beta status plus an irreversible action remains, per Digital Applied, a risky combination as long as the feature hasn't left beta.

Watch items. (a) Whether and when Claude Fable gets voice access. (b) Whether Anthropic follows the simultaneous listen-and-speak capability of OpenAI's GPT-Live family with its own full-duplex variant — so far with no stated timeline.

Substack / First-User Report July 23, 2026

Two years of manual work in a single recording: a content-repurposing skill that now posts to Threads, X, and Facebook itself

Charlie Hills · MarTech AI (charliehills.substack.com)

Problem. For two years, Hills manually re-cut every social post for Threads, X, and Facebook and scheduled each one individually in Buffer — Threads requires a broken-up thread, X a shortened version, Facebook the long form.

Stack. Cowork with Record a Skill, Notion (as the source for caption and image, read via connector), Buffer (controlled via "Control Chrome"/Claude in Chrome), followed by a daily scheduled task.

  • Performed the entire task once as usual, narrating out loud what she was doing and why — including the platform-specific rule that Threads gets broken up but Facebook doesn't get shortened.
  • Stopped the recording; Claude reads back the demonstration and splits the build across three parallel sub-agents: one writes the skill file, one the platform rules as a reference, one packages both together.
  • Tested the resulting "repurpose-to-buffer" skill in a fresh chat via slash command, with "Control Chrome" enabled, before relying on it.
  • Turned it into a scheduled task running daily on weekdays at 8 a.m. with a single additional sentence ("Let's make this a scheduled task").

Result. The job she did manually for two years now runs automatically — Claude itself chose the appropriate route for each step (Notion via connector, Buffer via browser control) rather than just blindly replaying mouse clicks. Honest caveat: because the task controls the real browser, the Mac has to stay awake and logged into Buffer — if the machine sleeps, nothing gets half-published; the finished post is simply prepared and the run stops. A reader comment from July 23 also reports that the feature only worked on Mac for them, not Windows.

Who it's for. Anyone with a weekly recurring, cross-platform repurposing or scheduling job that can be explained out loud in one pass.

Read more

The workflow in detail. Hills provides a concrete narration template to follow: "I'm doing [TASK] so that [OUTCOME]. First [ACTION], because [REASON]... Here's the tricky part: [THE RULE THAT CHANGES DEPENDING ON THE CASE]." The emphasis is on the why of each step — that's the part Claude translates into the skill, not the raw sequence of clicks.

Pitfalls. Claude records every single click; anyone who wanders off into an unrelated tab during the recording gets that baked into the skill as a fixed part of it, repeated on every run. Hills' own summary: the skill copies exactly what you do — the clean parts as much as the sloppy ones.

Applying this to your own context. The pattern transfers directly to your own recurring click workflows — say, a research or publishing step you already do the same way every week. The decisive point from this report isn't the technology but the discipline beforehand: do the job once, cleanly and without wandering off, because that is exactly what gets recorded and repeated forever.

Substack / Hands-on Test July 23, 2026

An Upwork job worth up to $100 an hour, rebuilt from a single screen recording

Gencay · LearnAIWithMe (learnwithmeai.com)

Problem. A 17-hour-old Upwork posting for a "Senior Data Scientist" called for a market intelligence pipeline that brings a stock's risk metrics together with its related news on a single screen — hourly rate $65 to $100, already more than 50 competing bids.

Stack. Cowork with Record a Skill; market data and news sources for a five-tile dashboard (volatility, drawdown, correlation, exposure, return), a price comparison of two securities, and a headline triage table.

  • Opened Cowork, selected "Record a Skill," and built the dashboard for real, once.
  • After stopping, Claude checks whether the recording is usable and, if so, generates a named skill from it.
  • Then used the resulting skill to build the actual, client-ready dashboard.

Result. The five-part dashboard with risk metrics alongside headlines was done, by her own account, in 15 minutes — for a task that fetches up to $105 an hour on the job market. Openly stated caveat: "A lot of my recordings never became skills, and I don't know why. It's still a very new feature." The full build process is behind a paywall.

Who it's for. Freelancers and consultants who want to quickly turn a recurring analysis task into a reusable, resellable skill — with the caveat that, per this report, the recording-to-skill conversion is still unreliable.

Try this week

Try it~20 min

1 · Test Record a Skill on a real, recurring click workflow

Pick a workflow that runs identically every week and can be narrated out loud in one pass — for instance, a research or publishing step from your own routine. Do it once, cleanly, speaking every rule and exception out loud, then test the resulting skill on a fresh example before letting it run live. Charlie Hills' core rule applies one to one: don't wander off, or the detour becomes part of the skill.

Check~15 min

2 · Run a private, connector-bound Artifact dashboard test — deliberately not public

Have Claude build a small internal dashboard over tools you already have connected, and experience the live-data/public-link exclusivity directly: as soon as an Artifact calls a connector, it stays private or organization-internal. For anything meant to end up public and readable by anyone without a login — like your own Webzeitung — this is no substitute, but for a personal tracking view, the test is worthwhile.

Test~10 min

3 · Try voice mode with a single connector for a commute

Enable one connector — calendar or Gmail is enough for the first test — and choose Opus or Sonnet instead of Haiku as the voice model. The most sensible first test case is read-only: ask for the afternoon's appointments or have an email thread summarized, rather than having something written or sent, as long as the feature remains in beta.

Editor's view & Trends

  1. Two frontier labs placed the same bet on demonstrating-instead-of-describing within five weeks of each other. Codex's "Record & Replay" (June 18) and Cowork's "Record a Skill" (July 21) solve the same problem: most operational knowledge is tacitly present but never written down — demonstrating it with an explanation makes it machine-readable without anyone having to formulate a specification. The real competition is thus shifting from benchmark numbers to the question of whose desktop client becomes the stage on which employees demonstrate their work.
  2. Three new features in two weeks, one recurring safety pattern. Record a Skill requires narration out loud before automation, Artifacts let every viewer see and act only through their own connector permissions, voice mode explicitly asks for consent before any action on a connected tool. That's not a coincidence but a consistent design principle: every new modality gets the same explicit approval step before Claude changes anything in connected data.
  3. The July 23 voice-mode split is the clearest snapshot yet of two strategies. Anthropic is investing in intelligence and tool access at a deliberately unnatural rhythm; OpenAI in natural, simultaneous speech without the same tool depth. For office use, the first bet is currently the more useful one — for consumer assistants, more likely the second.

Wildcard for the notebook: if the live-data/public-link limit on Artifacts actually falls next, an automation recorded with Record a Skill could feed directly into a publicly accessible, self-updating dashboard — three building blocks introduced independently of each other this week would combine into a single chain, without a single line of code.
