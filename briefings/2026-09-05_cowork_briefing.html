Home Stack — Claude Code & Cowork

Anthropic / Claude Code TRY 1–4 Sep 2026

Five point releases quietly fix permission and sandbox rules that weren't actually blocking

Across v2.1.257–v2.1.260, Anthropic fixed a run of permission bugs: Bash Read() deny rules that didn't cover option values, git operands, or cd compounds; Edit/Write/Read rules with parentheses being silently dropped as invalid; and one bad rule that broke all file edits with an opaque regex error. A macOS 12 launch regression got an emergency same-day patch.

None of this changes what Claude Code can do — it changes whether the guardrails you already wrote were doing anything.

Context & background. Deny-rule regex handling in settings.json has always been the sharp edge of Claude Code's permission system — a rule that looks right but doesn't compile the way the reviewer assumed is worse than no rule, because it reads as protection. This run of releases fixed at least four distinct classes of that failure inside four days, which says the surface area was larger than one bug.

The details. 2.1.259 fixed Read() deny rules missing option values, git operands and cd && compounds — meaning a rule meant to block cd /etc && cat shadow style compounds may not have fired. 2.1.260 fixed rules containing parentheses being rejected outright as "invalid," and separately fixed a single malformed rule anywhere in the list breaking every file edit in the session with a generic "Invalid regular expression" error rather than isolating the bad rule. 2.1.260 also reverted a 2.1.259 change that had over-corrected in the other direction, denying legitimate commands like npm run build. 2.1.261 added bashOutputMaxChars/taskOutputMaxChars (output can now stay inline to 128K characters before spilling to file) and /skill-doctor to show which loaded skills are unused and their context cost.

Why it still matters. Anyone running Claude Code with custom deny rules against a pipeline holding client, deal or financial data has been relying on protection that had known gaps for an unknown window. There's no CVE and no disclosure beyond the changelog entries themselves — this is bug-fix hygiene, not an advisory, so nothing forces anyone to re-check their own rule sets against the new behaviour.

Anthropic / Claude Code WATCH 1 Sep 2026 · v2.1.257/260

Claude Fable 5.1 becomes the default subagent model, with a new flag to force it everywhere

v2.1.257 shipped Claude Fable 5.1 (1M context, $10/$50 per Mtok, $0.25/Mtok cache reads) as the new default Fable-tier model and added CLAUDE_CODE_SUBAGENT_MODEL_FORCE to pin every subagent to one model regardless of what a skill or command frontmatter requests. v2.1.260 fixed prompt caching on Fable 5.1 not covering context after tool results — a real cost bug on exactly the workflows (long tool-heavy subagent runs) the model targets.

Fable 5.1 also carries safety-triggered auto-fallback to Opus on flagged request categories, toggleable in Config > MODEL & OUTPUT.

Claude Code changelog Model-switching support article
Read more

Context & background. Subagent model selection has been a quiet cost lever in Claude Code: skills and slash commands can request a specific model via frontmatter, but until this release there was no single override to guarantee every subagent in a session runs the same model — useful for cost audits or for pipelines that need deterministic behaviour across a fleet of parallel subagents.

The details. The prompt-cache bug fixed a day later (2.1.260) meant subagent runs that call tools mid-task — the majority of real work — weren't getting cache discounts on everything after the first tool result, silently inflating token bills on exactly the default model just promoted.

Why it still matters. A default-model flip inside an existing product is not new capability, but it is a cost and behaviour change that lands without anyone opting in. Anyone running subagent-heavy workflows (this pipeline included) should check actual spend against the new default before assuming the promotion was cost-neutral.

Anthropic / Cowork TRY 25 Aug 2026

Cowork and Claude chat now share one memory — off by default on Team and Enterprise

Claude's memory system merged across chat and Cowork: preferences and project context set in one now surface in the other, updated live during a session rather than only summarised at its end. It's on by default for Free, Pro and Max; off by default for Team and Enterprise accounts.

Sensitive categories (health, religion, race, ethnicity, gender identity) are excluded unless a user opts in; government IDs and criminal history are never stored regardless.

TechCrunch The New Stack SD Times
Read more

Context & background. Cowork and chat previously ran separate memory stores, which meant re-explaining a project's context every time work moved from a chat conversation into a Cowork session or back — exactly the seam an operator running both surfaces for one pipeline hits constantly.

The details. The update writes memory continuously rather than at session end, and users can view, edit or delete stored entries directly. Claude remains ad-free, so nothing written to memory feeds ad targeting. Multiple outlets (TechCrunch, The New Stack, SD Times, 9to5Mac, Engadget) independently confirmed the same rollout and defaults; no Anthropic newsroom post was found separate from in-product documentation.

Why it still matters. The Team/Enterprise default-off split is the operational detail: an operator on a Team or Enterprise seat gets none of this until they turn it on manually, while a Pro or Max user gets it automatically. Worth checking which side of that line this pipeline's account sits on before assuming continuity that isn't there yet.

Across the stack

Cursor WATCH 2 Sep 2026

Cursor lets Cloud Agents run entirely on customer-owned infrastructure

"Self-hosted machines" moves Cloud Agents off Cursor's infrastructure and onto AWS Lambda, Coder, Cloudflare, Daytona, Modal, Namespace, Vercel or E2B — code, build outputs and secrets stay on internal machines, with dynamic worker pools that scale and hibernate on demand.

It follows two weeks of Cloud Agent expansion: subscriptions that wake agents on PR or Slack events, a /goal command for long-lived objectives, and non-blocking steering mid-run.

Cursor changelog Self-hosted pool docs
Read more

Context & background. Cloud coding agents have had one standing objection from security-conscious teams: code and secrets leave the building. Cursor's own Cloud Agents (and the /goal-driven autonomous mode shipped 19 August) inherited that objection along with the convenience. Self-hosted machines is Cursor's direct answer — not a new agent capability, but a deployment model that removes the objection.

The details. Named worker queues scale with demand and support hibernation to control idle cost; self-hosted workers also support computer use (browser and application interaction) on Linux and Mac, not just terminal/tool-call agents. Setup targets platform teams provisioning infrastructure, not a single operator wiring up a personal pool.

Why it still matters. This is a data-residency and compliance play aimed at regulated or security-sensitive engineering orgs, not a capability delta for a solo or small-team pipeline. The open question is whether Anthropic answers with the same option for Claude Code's own cloud/background sessions.

Watch items. Flips to TRY once a self-hosted pool has a documented single-command setup for a one- or two-person team, rather than requiring a platform-team-scale deployment.

Google / Gemini CLI TRY 1 Sep 2026 · v0.58.0

Gemini CLI v0.58.0 locks down container access after a sandbox-escape-shaped gap

The stable release isolates Docker and container-runtime sockets and binaries inside macOS Seatbelt sandboxing, closing a path to unauthorized container execution. It also fixes inconsistent symlink evaluation in ignore-path handling and adds top-level safety checkers to write-policy configuration.

Gemini CLI changelog v0.57.0→v0.58.0 diff
Read more

Context & background. Sandbox isolation on macOS Seatbelt is Gemini CLI's main defence against a misbehaving or manipulated agent reaching outside its intended scope. A gap in container-socket isolation specifically means an agent running Docker commands could have had broader execution access than the sandbox model intended.

The details. Seven pull requests shipped in this release; alongside the sandbox fix, ignore-path symlink handling was made consistent (a previous inconsistency could let excluded paths resolve back into scope via a symlink) and write-policy configuration gained safety checkers at the top level rather than nested.

Why it still matters. This is a straightforward upgrade-now item for anyone running Gemini CLI in containerized workflows on macOS, independent of whether Gemini CLI is this pipeline's primary agent. Low effort, real risk closed.

Editor's view

  1. The Home Stack's real news this week is a security correction, not a feature. Four consecutive point releases fixing deny-rule and sandbox gaps means the permission system anyone relies on to run Claude Code against sensitive data had known holes for an unknown window — worth an actual audit, not just reading the changelog.
  2. Cursor's self-hosted machines is the more strategic move than any single Claude Code point release. It's Cursor conceding that the cloud-agent pitch stalls without an on-prem answer for regulated teams. The next thing worth watching is whether Anthropic offers the same option for Claude Code's own cloud and background sessions — nothing suggests it's coming yet.
  3. Everyone else moved on plumbing, not capability. Gemini CLI's sandbox hardening, Devin's scan tooling and connector expansion, and the MCP roadmap post are all maintenance, governance or code-quality work — nothing here lets an operator do something this week that wasn't possible in July.

A quiet week for new capability is not the same as a quiet week for risk — this one had more of the latter than the former.
