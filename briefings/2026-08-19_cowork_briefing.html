Anthropic / Claude Code TRY Shipped Aug 14, 2026

Claude Code's auto-mode default shipped exactly on schedule — but Enterprise, API and cloud-platform accounts stayed opt-in

The flip to auto-mode-by-default for Pro, Max and Team plans landed on August 14 as announced the week before, with no reported delay or rollback. What last week's coverage didn't nail down: the default only applies to those three consumer/team tiers. Claude Enterprise, the Claude API, Claude Platform on AWS Bedrock, Google Cloud's Agent Platform and Microsoft Foundry all remain opt-in — auto mode has to be turned on deliberately there, not switched off.

That carve-out is the operationally relevant fact this week, more than the classifier numbers already covered: it determines whether a given Claude-based workflow inherited the new default automatically or not.

Last week's edition flagged one open question ahead of the flip: whether this pipeline's own Sonnet subagent dispatches, run through Cowork's own orchestration rather than a raw interactive Claude Code CLI session, would be swept into the new default. This week's carve-out list answers part of that — anything running on an API key rather than a Pro/Max/Team login stays on the opt-in track by default.

The details. The carve-out was not prominent in the original announcement or last week's coverage; it surfaced only in the fuller product documentation once the flip actually shipped. No practitioner report this week describes a Claude-Code-run pipeline breaking or unexpectedly auto-approving a destructive step — the rollout reads as clean so far, though a week is a short window to judge an unattended-automation change.

Anthropic / Claude Code WATCH Aug 11–18, 2026 · v2.1.228–v2.1.235

Eight Claude Code point releases in eight days include a critical OAuth fix and the first cross-session collaboration feature

Between v2.1.228 (Aug 11) and v2.1.235 (Aug 18), Claude Code shipped roughly one release a day: a fix for interactive sessions freezing visually while still running, a critical OAuth sign-in fix (v2.1.231, Aug 13) that had been blocking connections to services like Slack, GitLab merge-request support in the worktree view plus memory limits against runaway build commands (v2.1.233), the ability to @-mention and collaborate across separate Claude sessions by name (v2.1.232), automatic session continuation when usage limits reset (v2.1.234), and optional inline spellcheck plus background-task handling improvements (v2.1.235, the day before this edition).

None of the eight is a breaking change to scripted, non-interactive use the way the auto-mode default is — this is reliability and UX hardening at a denser cadence than the four-release window covered last week.

Anthropic / Cowork SKIP Aug 12, 2026

Claude Cowork replaces the old Chrome side panel — full sessions, skills and connectors now run inside the browser

On August 12, Anthropic replaced the "Claude in Chrome" side panel with a full Claude Cowork session: conversation history, skills and connectors carry over, and a task started in a browser tab can be picked up on desktop, web or mobile. It's live now for Max and Team plans, rolling out to Pro over the coming weeks.

This widens where a Cowork session can be started, not what one can do — the underlying capability is the same Cowork already running this pipeline's sessions elsewhere.

MCP ecosystem WATCH Spec Jul 28 — adoption through Aug 19

MCP's stateless spec picks up its first named adopters: Codex, Cloudflare's Agents SDK, and an enterprise-auth trio

Last week's protocol change — dropping session state, the Mcp-Session-Id header, and the requirement to pin a client to one server instance — now has concrete adopters. OpenAI's Codex CLI added support for the 2026-07-28 spec this week; Cloudflare's Agents SDK supports it "from day zero," letting customers such as Sentry and Linear pick it up without a server-side migration; and the previously-stabilized Enterprise-Managed Authorization extension is being adopted jointly by Anthropic, Microsoft and Okta.

Two client-side vendors and one infrastructure vendor moving in the same three-week window is the first real evidence the spec is being built against, not just published.

Context & background. The spec itself shipped July 28 and was covered at 5/5 confidence last week as a primary-source protocol change; this week is the first evidence of adoption rather than a further protocol revision.

The details. Cloudflare's "day zero" framing matters because it means any Cloudflare-hosted MCP server gets the stateless, horizontally-scalable behavior automatically — the benefit lands for customers without them doing anything, which is a faster adoption path than most protocol changes get. Codex's adoption is the more directly relevant signal: a major agent CLI now speaks the new handshake, which is the kind of cross-vendor interoperability MCP's stateless design was built to enable.

Why it still matters. Unchanged trigger from last week — this pipeline consumes hosted MCP connectors rather than running its own server, so the simplification stays a watch item until that changes. Worth logging that three vendors moved in the first three weeks after the spec shipped, faster than a typical protocol-adoption curve.

Cursor WATCH As of Aug 19, 2026 — unchanged

Cursor's Opus-4.8-beating router claim still has no independent benchmark behind it, a week later

Following up on last week's open question: no third-party benchmark of Cursor's Auto Balance router against Opus 4.8 has surfaced. What exists instead is more detail on Cursor's own methodology — the company measures the router through large online A/B tests against live production traffic rather than offline evals, on the stated logic that model selection should be learned from real developer work rather than inferred from benchmark scores.

That's a defensible argument for why an offline benchmark might understate a router's real-world value, but it also means the 41%-cheaper, Opus-4.8-beating headline number is still Cursor grading Cursor, on data no outside party can reproduce.
