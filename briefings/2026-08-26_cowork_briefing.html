Home Stack — Claude Code & Cowork

Anthropic / Cowork TRY Shipped Aug 25, 2026

Claude's memory now follows you from chat into Cowork by default — no more re-briefing between surfaces

Anthropic merged its two separate memory systems on August 25: Claude now "starts from what it already knows about you" whether the conversation began in chat or in a Cowork session, and updates that memory continuously as a conversation happens rather than summarizing only at the end. It's on by default for Free, Pro and Max plans, on web, desktop and mobile (Team/Enterprise leaves activation to admins). Users can view, edit, pause or fully reset what's stored.

Anthropic's stated default exclusions match the sensitive-category list this pipeline's own memory guidance already follows — health, race, ethnicity, religion, politics, gender identity are kept out unless a user opts in, and government IDs, criminal history and immigration status are refused outright.

Context & background. Before this merge, a fact learned in a chat conversation stayed invisible to a Cowork session working the same problem, and vice versa — exactly the kind of re-briefing friction the Aug-14 auto-mode default and the Aug-12 Cowork-on-Chrome expansion (both covered in prior editions) were chipping away at from the automation and reach angles rather than the context-continuity angle.

The details. The real-time update behaviour is the more consequential change than the cross-surface merge itself: memory used to be written as an end-of-conversation summary, so a correction made mid-session (a changed deadline, a corrected fact) could be lost if the conversation ended abruptly. Continuous updating closes that gap. The opt-in sensitive-category list is disclosed, not just implied — Anthropic names the excluded categories explicitly in the announcement, which is unusually specific for a memory-launch post.

Why it still matters. Worth an hour this week: open Memory settings on whichever plan runs this pipeline's own Claude usage and check what's already been captured, particularly from any session that touched confidential business context (Pet Food supplier relationships, unreleased content). If Team/Enterprise governs this pipeline's account, confirm with the admin whether memory has been activated org-wide before assuming it's off.

Anthropic / Claude Code TRY Aug 20–25, 2026 · v2.1.237–v2.1.246

Claude Code's security defaults tighten again — a wildcard Bash-rule warning and mandatory approval before a plugin can mint its own auth tokens

Across eight point releases this window (v2.1.237 to v2.1.246), two changes are worth checking your own setup for. v2.1.246 (Aug 25) added a startup warning when a Bash allow rule has a wildcard placed before the subcommand — e.g. Bash(git * main) — because such rules also match options inserted ahead of the subcommand, a gap that could silently widen what a rule actually permits. v2.1.238 (Aug 20) introduced headersHelper for plugin marketplaces: a plugin can now mint its own short-lived HTTP auth tokens, but only after its minting command is shown to you and you approve it at install or update time, and MCP servers using the same mechanism now require the folder's trust dialog to have been accepted first.

Both read as direct responses to the failure class this briefing has tracked before: April's "deny rules silently bypassed after 50 subcommands" disclosure and August's CVE-2026-54316 API-key-exfiltration flaw both involved untrusted content or configuration reaching a Claude Code session without the operator noticing.

Context & background. Last week's edition covered a separate eight-release window (v2.1.228–v2.1.235) as reliability hardening with one critical OAuth fix; this window keeps the same one-release-a-day cadence but shifts weight toward permission-and-trust surfaces specifically, rather than connector reliability.

The details. The Linux crash fix (v2.1.245, Aug 25) is the other headline item: a startup crash on distributions shipping glibc 2.44 — Arch Linux, CachyOS, Fedora Rawhide — that would have blocked Claude Code entirely on affected machines until patched, though it is a compatibility bug rather than a security issue. Separately, v2.1.245 fixed cross-session messaging silently turning off inside user namespaces and rootless containers, a regression traced back to the 2.1.232 socket-directory hardening two weeks ago — a reminder that security hardening itself can introduce its own quiet breakage.

Why it still matters. Worth the hour: run /permissions and look specifically for any Bash allow rule with a wildcard before the subcommand, since that is the exact pattern v2.1.246 now flags at startup — this pipeline's own auto-mode classifier rules are worth a pass. No plugin marketplace with a headersHelper is currently installed on this pipeline's setup, so the approval-gate change itself needs no action beyond noting it exists before adding one.

Cursor WATCH Aug 19–20, 2026

Cursor's cloud agents move from one-shot triggers to standing subscriptions — "swarms" of isolated subagents and a /goal command for unattended work

Cursor shipped a set of changes aimed squarely at reducing babysitting: cloud agents can now subscribe to a PR, a Slack thread or a cron schedule and wake only when something happens, rather than running once and stopping; a new /goal command gives an agent a long-lived objective to keep working toward; and subagents now each get an isolated VM with a clean project copy, enabling parallel "swarms" that can't step on each other's file edits. This builds on Cursor's existing Automations (launched March 2026) rather than replacing them.

The framing is explicit: Cursor wants agents to "operate as a system... without the need for intervention at each loop" — a materially bigger autonomy claim than a faster completion or a new panel.

Context & background. This is Cursor's most direct move yet toward the always-on, cross-session agent behaviour Claude Code has been building piecemeal (cross-session SendMessage/ListAgents, background sessions, /goal check-ins of its own) — the two products are now visibly converging on the same shape rather than differentiating.

The details. Cursor's own changelog carries no disclaimer about autonomy limits, failure rates or when a subscribed agent should be expected to ask for human input rather than act — a gap this briefing flagged for Cursor's router-benchmark claim two weeks running, now showing up again for a capability claim rather than a performance one.

Why it still matters. Trigger to flip to TRY: an independent practitioner report of a subscribed cloud agent running unattended for multiple wake cycles without a bad edit or a runaway action — nothing that specific has surfaced yet. Worth testing only once that evidence exists, given this pipeline's own scheduled-task history includes exactly the kind of unattended-automation risk this feature is designed for.

GitHub / Copilot WATCH Aug 21 & 25, 2026

GitHub Copilot lands as a full agentic surface inside Slack and Microsoft Teams, plus an MCP-based Customize tab

GitHub shipped Copilot into Slack (public preview, Aug 21) and Teams (Aug 21) as a shared, collaborative agent: mentioning @GitHub in a channel starts a session the whole team can watch and steer, not just a single user's DM. Four days later (Aug 25), a new Customize tab in the Copilot app added direct Model Context Protocol integration, letting Copilot reach into whatever MCP servers a team already runs.

This is the same "meet the team where they already work" bet Cowork made with its own web and mobile expansion in July and Chrome side-panel move in August — GitHub is making it inside chat tools this pipeline doesn't currently route through.

Editor's view

  1. Memory, not another model or another IDE panel, is this week's biggest operator-facing change. A default-on, cross-surface memory system changes what Claude already knows before a session starts — that's a bigger day-to-day shift than another point release, and it's the one item this edition rates worth an hour precisely because it changes behaviour by default rather than waiting to be opted into.
  2. Security hardening keeps arriving as small, load-bearing defaults rather than headline features. A wildcard Bash-rule warning and a mandatory approval step before a plugin can mint its own auth tokens will not make anyone's release notes summary, but both close gaps in the same failure class — untrusted content or configuration reaching a session unnoticed — that produced a real CVE and a real deny-rule bypass earlier this year.
  3. Every major agent tool is chasing the same "operate without me" claim at once. Cursor's standing subscriptions, GitHub Copilot's shared Slack/Teams sessions, and Claude Code's own background and cross-session messaging features are all pointed at the same target — less babysitting — and none of them has third-party evidence yet that the autonomy claim holds up outside the vendor's own telling.

Wildcard for the week: GitHub Copilot showing up natively inside Slack and Teams is worth remembering less for what it does today than for the bet it represents — that the agent should live inside the chat tool a team already has open, rather than pulling the team into a separate agent surface the way Cowork's own expansion has.
