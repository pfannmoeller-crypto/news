Home Stack — Claude Code & Cowork

Anthropic / Claude Code TRY 2.1.265–2.1.271 · Sep 8–14, 2026

Auto mode now sends inline shell commands and subagent hand-backs through the safety classifier

Three point releases close a gap in auto mode: a skill's or slash command's inline ! shell commands used to follow the classifier's judgment call, and a subagent's work reached its caller through its own last message rather than a reviewed hand-back. Both now run as reviewed tool calls like everything else auto mode approves.

The same run of releases also killed the no-timeout Monitor watch. Every watch now carries a deadline — 30 minutes at most, 10 in a single-prompt -p run — and Claude has to notice and re-arm it rather than leaving one open indefinitely.

Context & background. Auto mode's safety classifier is meant to review every consequential tool call before it runs; the two gaps it closes here were both places a call could take effect without going through that review — an inline shell command tucked inside a skill's own script, or a subagent's summary standing in for an actual reviewed report. The fix landed in three steps: 2.1.265 didn't touch this directly, 2.1.269 introduced the inline-command and Monitor-deadline changes alongside a revert of an over-broad 2.1.259 deny-rule change, and 2.1.270 had to fix a regression where read-only git commands started asking for permission after a long-running session. 2.1.271 then reissued the inline-command and subagent hand-back changes cleanly, plus a new per-command allowed_domains option for Bash, PowerShell and Monitor in auto mode.

The details. Concretely: a skill that shells out with !some-command inside a markdown body no longer gets a free pass from the classifier — it is now scoped by the same permission rules as a directly issued Bash call. A subagent's result now arrives at its caller through a dedicated hand-back call, which the classifier reviews on its own terms, instead of the caller simply trusting the subagent's closing message. Monitor's persistent option — the one that let a watch run with no timeout — is gone; every watch, however set up, now expires and needs Claude to re-arm it.

Why it still matters. This pipeline runs under auto mode and uses Monitor itself; a watch set up assuming it would sit open indefinitely will now lapse silently unless something notices the deadline and re-arms it. Any skill in this stack that shells out inline should be checked against the current permission rules rather than assumed to have run under the classifier's looser read before 2.1.269.

Anthropic / Claude Code TRY 2.1.268 · Sep 10, 2026

A managed MCP server you thought you'd filtered out can reappear on upgrade

allowedMcpServers now governs only the servers a user or project adds themselves; a literal managed-mcp.json entry your allowlist used to exclude now loads again after upgrading past 2.1.268, and keeping it off requires deniedMcpServers instead. The same release also stopped plain WebFetch deny and ask rules from reaching the Artifact tool's own reads and updates — an Artifact rule is now required to gate those.

Context & background. The two changes shipped in the same release because both narrow what a single settings rule is assumed to cover. allowedMcpServers was being used, in practice, to keep an org-managed server off a machine even though the field was meant to scope user additions; that filtering effect is now gone. Separately, the Artifact tool fetches and publishes pages over the network, which made a WebFetch rule look like it covered Artifact calls too — it no longer does.

The details. The release bundles a related fix: WebFetch itself used to hang indefinitely on a slow or unresponsive host; it now fails after 300 seconds by default, adjustable through CLAUDE_CODE_WEBFETCH_DEADLINE_MS. A separate fix in the same version closed a gap where deny and ask rules on a symlinked directory didn't apply when a path was given by its real, non-symlinked location.

Why it still matters. Any configuration that leaned on allowedMcpServers to keep a specific managed server out, or on a WebFetch deny rule to gate the Artifact tool, should be re-checked against 2.1.268 and later — the old assumption about what those rules cover no longer holds.

OpenAI / Codex CLI WATCH v0.154.0 · Sep 9, 2026

Codex CLI adds isolated worktree sessions and lets you answer questions without breaking its stride

The previous edition of this briefing dropped Codex CLI for a changelog gone quiet since June — that read turns out to be wrong. Codex shipped continuously through July and August and landed v0.154.0 on 9 September: experimental worktree support (--worktree or /worktree) creates an isolated checkout for a new or forked session, and questions can now be answered inline, with suggested choices or free text, while Codex keeps working instead of stalling on the prompt.

The same release shares a background Codex server across Windows sessions with new daemon lifecycle commands, and drops the already-deprecated codex mcp-server entry point entirely — a hard break for any config still pointing at it.

Context & background. Codex CLI's pace has actually been high all summer — 0.143–0.146 shipped through late July, 0.150–0.153 through August, and 0.153.0–0.154.0 in the first two weeks of September, including plugin-marketplace support for the CLI (list, install, remove from remote marketplaces) that landed 3 September. None of that surfaced in this briefing's prior editions; it should have.

The details. Worktree support is explicitly experimental and creates its own checkout per session rather than sharing a working tree, which avoids one session's edits colliding with another's. Inline question-answering means a long-running task no longer has to pause and wait at a terminal prompt — Codex surfaces the question with suggested answers and keeps its context. The Windows background-server change lets multiple sessions share one daemon instead of each spinning up its own process. The removed codex mcp-server entry point was deprecated earlier and is now gone outright, breaking any script or agent config still invoking it directly.

Why it still matters. Worktree isolation and inline mid-task Q&A are both genuinely useful, comparable capabilities to things this stack already does with Claude Code sessions and hooks — worth a side-by-side hour once worktree support leaves "experimental." Anything integrating with Codex through the old mcp-server command needs to move off it now, not on notice.

Cursor WATCH Beta · Sep 10, 2026

Cursor's new coordinator agent delegates whole features and migrations to cloud subagents

Cursor Projects, in beta to all users since 10 September, adds a coordinator agent that plans and delegates rather than writes code itself, spreading work across parallel cloud subagents for features, large migrations, or ongoing maintenance like lint-rule generation. Projects keep running on dedicated cloud machines when a laptop closes, and a coordinator can subscribe to a Slack channel, a schedule, or every PR on a repo to act without a fresh prompt each time.

Cursor: Introducing Projects AI Weekly coverage

Context & background. This is Cursor's answer to the same problem this pipeline already solves with unattended Claude Code sessions and scheduled tasks: keep an agent working on something larger than one prompt-response turn without a human babysitting it. Cursor's framing — a coordinator that "delegates rather than executes, is never blocked" — is explicitly aimed at multi-week, multi-PR work rather than single edits.

The details. The coordinator can spin up a local agent when a task needs to run against a developer's own machine, otherwise everything stays in the cloud. Cursor reports new users merging 30% more pull requests and heavy users merging six times as many — both figures are self-reported, unaudited, and published without a baseline or cohort breakdown.

Watch items. Beta rollout, self-reported productivity numbers, and no published detail yet on data residency or what a coordinator is blocked from doing autonomously (the announcement doesn't state whether pushing to main is restricted). The trigger to revisit: general availability plus an audited benchmark or a clear data-handling spec.

GitHub / Copilot TRY Sep 7–11, 2026

Copilot code review now closes its own comment threads, and VS Code learns to run agents on a schedule

VS Code 1.137 (week of 7 September) adds recurring agent tasks in public preview — hourly, daily, weekly, or on demand — plus experimental voice mode and PR/issue review inside the Agents window. Separately, on 11 September, Copilot code review started resolving its own comments automatically when a follow-up commit addresses them, and writes a specific commit message when a developer applies one of its autofixes instead of a generic default.

GitHub also rolled out an ensemble "Lite" review mode that combines several model passes into one set of findings: in GitHub's own testing it raised the share of addressed high-severity comments by 47% (31% medium, 11% low) while cutting review cost by about 8%.

Context & background. Both changes target the same friction point: a reviewer (human or Copilot) leaves a comment, the fix lands in a later commit, and someone has to remember to close the thread. Auto-resolution removes that manual step; the ensemble mode is GitHub trying to make the underlying comments worth resolving in the first place, by combining perspectives before a single verdict reaches the PR.

The details. The ensemble approach also gained "a broader set of shell tools" behind Copilot's agent firewall, so it can validate a fix by actually running build and test commands rather than reasoning about the diff alone. JetBrains gets a parallel but separate change: enterprise admins can now centrally set sandbox policy — enablement, filesystem and network access, proxy settings — through managed policies (public preview).

Why it still matters. This is a concrete, low-cost test: point the Lite ensemble review at one real pull request from this pipeline's own tooling and compare what it flags, and at what cost, against the current review step. Recurring scheduled agent tasks in VS Code are also worth a look against any chore this pipeline still runs by hand on a timer.

Google / Gemini CLI TRY v0.59.0 · Sep 8, 2026

Gemini CLI patches an MCP OAuth SSRF gap and locks workspace trust fail-closed

v0.59.0 fixes a server-side request forgery vector during MCP OAuth metadata discovery and authentication, and moves workspace trust to fail closed: in restricted mode, the set of MCP servers available to a session is now filtered rather than left open. It follows the v0.58.0 sandbox-container hardening this briefing flagged TRY two editions ago — the pattern is a team working through its own attack surface release by release.

Context & background. MCP OAuth metadata discovery involves the CLI fetching a URL supplied by the server it's authenticating against; without validation, that fetch can be redirected to an internal address the attacker wants probed — the classic SSRF shape. Fail-closed workspace trust means an untrusted or restricted workspace no longer gets the benefit of the doubt on which MCP servers it can see.

The details. The changelog describes the fix as preventing SSRF specifically "during MCP OAuth metadata discovery and authentication" and the trust change as filtering "available mcpServers when operating in restricted mode" — both narrowly scoped to the MCP integration rather than a CLI-wide change.

Why it still matters. Any Gemini CLI install configured with MCP servers should move to v0.59.0; an OAuth-discovery SSRF is a real, exploitable class of bug, not a theoretical one, and the fix is a version bump, not a config migration.

Cognition / Devin SKIP Sep 9–11, 2026

Devin added 21 new zero-config OAuth MCP servers to its marketplace on 11 September — Dropbox, ClickHouse Cloud, Lucid, Typeform, Coda, GitBook, Railway, Retool, Smartsheet and Make among them — alongside a unified plugin system for bundling skills, rules, hooks and MCP servers into installable, org-governed packages, a PagerDuty on-call integration, and new /scan and /ask slash commands.

Editor's view

  1. The permission story is the real Home Stack news. Claude Code's auto mode spent September closing the gap between what the safety classifier was assumed to review and what it actually reviewed — inline shell commands, subagent hand-backs, and now MCP-server and WebFetch scoping that quietly stopped meaning what a config file said it meant.
  2. Dropping Codex CLI for going quiet was a mistake worth naming. It shipped through the whole gap this briefing wasn't watching it — plugin marketplaces, worktree isolation, inline Q&A — and none of that is model news; it belongs here every week Codex CLI ships something, not just when it's convenient to notice.
  3. Everyone else is racing to "coordinator plus cloud subagents," and none of it is proven yet. Cursor Projects, Copilot's recurring agent tasks, and Devin's expanding marketplace are three different bets on the same shape of autonomy; the unaudited productivity claims and beta labels are why two of three land as WATCH or SKIP this week rather than TRY.

A quiet capability week, a loud plumbing one — the tools that ship security and permission fixes on a tight cadence are the ones actually running production work, this pipeline's own included.

What changed for this pipeline

  • This week, worth doing: audit this pipeline's Claude Code config for allowedMcpServers or deniedMcpServers usage and confirm no managed server silently reappeared after crossing 2.1.268; swap any long-lived Monitor watch for the new deadline-and-re-arm pattern introduced in 2.1.269–2.1.271.
  • Also worth doing: grep this pipeline's skills and slash commands for inline ! shell commands, and re-check them against default-mode permission rules now that auto mode no longer waves them through on the classifier's earlier judgment call.
  • Worth trying once, not urgent: run GitHub Copilot's ensemble "Lite" code review against one real pull request from this pipeline's own repo and compare its findings and cost to the current review step.
  • Not yet: hold off routing any of this pipeline's work through Cursor Projects or Devin's plugin marketplace until either publishes an audited benchmark, leaves beta, or states its data-residency terms plainly.
