What shipped this week

Claude Code / Substrate August 4–7, 2026

Claude Code patches seven sandbox and permission bypasses in three days, then ships self-hosted runners

Across three releases — 2.1.221 and 2.1.222 (both August 4) and 2.1.223 (August 6) — Claude Code fixed seven distinct ways a session's sandbox or permission checks could be sidestepped: a zsh regex-conditional trick and a tab/invisible-Unicode padding trick that both hid parts of a command from the approval prompt, a PowerShell quoted-path bug that skipped the prompt entirely, a worktree-isolation gap that let sessions run destructive git commands against the main checkout, a PreToolUse auto-allow hook that let background agents dodge tool restrictions during summaries and compaction, a further crafted-command bypass of the Bash permission check, and a dynamic import() trick that let workflow scripts run code outside the sandbox.

The cluster closes on a different note: version 2.1.224 (August 7) adds claude self-hosted-runner, which turns a user's own machine or container into a place where Claude Code's web, mobile, and desktop sessions can actually execute — available on Team and Enterprise plans.

Read more

Context & background. This lands exactly a month after Anthropic moved Claude Code and Cowork sessions off the local machine and into the cloud (Cowork's web and mobile beta, announced July 7). Once execution can happen somewhere other than the user's own laptop, the sandbox boundary around that execution becomes the thing that actually has to hold — which is the throughline connecting the bypass fixes to the self-hosted-runner release the same week. Worth being precise about scope: all of this is Claude Code (the CLI/agent product), not Cowork itself, even though the two increasingly share the same remote-session infrastructure.

The details. The seven fixes, by release: 2.1.221 — Bash tool permission-check bypass via zsh regex conditionals in [[ ]]; PowerShell permission checks mishandling quote characters in paths on Windows. 2.1.222 — worktree-isolated sessions and subagents able to run destructive git commands against the main checkout; a PreToolUse auto-allow hook bypassing tool restrictions in background agent tasks. 2.1.223 — a crafted command able to hide parts of itself from permission checks; commands padded with tabs or invisible Unicode hiding part of the command from the approval dialog; workflow scripts using dynamic import() to run code outside the workflow sandbox. Two further releases followed on August 8 (2.1.225, 2.1.226) with gateway spend-limit warnings, a workspace-trust prompt for untrusted directories, and further reliability fixes — no new bypasses disclosed in either.

Context for your stack. None of the seven bypasses map onto anything the webzeitung-briefings pipeline currently relies on — it doesn't use worktree isolation, background-agent PreToolUse hooks, or crafted Bash commands — but it's a reasonable five-minute check to confirm that directly rather than assume it. Self-hosted-runner itself isn't relevant yet: the pipeline already runs locally. It becomes relevant the moment any scheduled or cloud-triggered Cowork task needs to write into this local News folder without Anthropic's own cloud sandbox being the execution environment.

Watch items. Whether Anthropic publishes anything beyond the changelog line explaining self-hosted-runner's security model and setup requirements. Also carried forward unresolved: the stateless MCP specification's ten-week validation period, due to conclude July 28 per the last two issues, still has no confirmation of going final as of August 10.

MakeUseOf / Reference Playbook March 20, 2026 (older — reference)

A freelancer builds a Cowork Skill that ends up replacing their own five-year content retainer

Jonathon Jachura · MakeUseOf

Problem. Five years of writing Google Business Profile posts and social content by hand for a small local-business client, using Claude only as an editor — then a full-time job offer meant handing the work off cleanly within about a month.

Stack. Claude Cowork (macOS desktop), Claude Skills, a folder of brand guidelines, tone notes, roughly two dozen past example posts, and a basic prompt template — no code, no APIs.

  • Assemble a folder with the client's brand guidelines, tone notes, past example posts, and a prompt template.
  • Point Cowork at the folder and ask it to generate a month of Google Business Profile posts.
  • Run several rounds of prompt tweaking and Skill updates until tone, topics, and length matched what the client was used to.
  • Turn the working prompt into a reusable Claude Skill rather than a one-off session.
  • Demo the finished workflow to the client directly on an offboarding call.

Result. The client didn't ask for a replacement freelancer — they asked for the workflow itself, handed off so someone on their end can run it, review the draft calendar, edit, and schedule. The author is candid about the irony: they automated their own five-year gig, and still argue long-form writing isn't ready for the same treatment because it lacks the texture a model doesn't consistently nail.

Who it's for. Freelancers or in-house marketers running repeatable, template-driven content — social posts, GBP updates, content calendars — who want a concrete first-hand account of building a Cowork Skill through to handoff, caveats included.

Read more

The workflow in detail. The first pass out of Cowork "wasn't perfect — it rarely is with any new workflow — but it was genuinely close," per the author. What closed the gap wasn't a single better prompt but repeated rounds: tweak the prompt, update the Skill, regenerate, compare against the folder of past examples, repeat. Only once the drafts consistently matched tone, topic selection, and length did the author consider it finished enough to hand off.

Pitfalls. The author draws a hard line at skipping human review: "nobody knows a business the way the people running it do," and AI-generated content usually falls apart there — not from bad writing, but from missing the specific, ground-level knowledge that makes local content feel local. The handoff explicitly keeps a human in the loop for review, edits, and scheduling; the Skill only produces the first draft.

Applying this to your own context. The pattern maps onto any recurring, template-driven deliverable with a stable style and a folder of past examples to learn from — a beat like this one included. The open question worth testing directly: whether turning a specific recurring beat into a saved Skill, rather than re-reading a spec file fresh each run, measurably reduces how much re-explaining a run needs.
