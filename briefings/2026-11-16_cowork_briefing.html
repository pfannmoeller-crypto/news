Your stack: Claude chat 2 stories

Claude chatWATCHTOP12 Nov
Claude Meetings can now join a Google Meet call, take notes and build documents while you talk
Claude joins as a visible participant, answers questions in writing and writes the recap afterwards. It is a beta for Team and Enterprise plans only, and only for Google Meet so far.
●●●●● 5/5
The details

Claude appears in the call as a named participant and posts a notice in the chat. Say “Claude, start a doc for this plan” and it drafts one that teammates on the invite can edit live; it can also put a schedule on a whiteboard. It uses your connected tools only with your permission and asks again each time when someone asks out loud. It saves a transcript, a summary and descriptions of shared screens, not the audio. By default Claude stays out of calls with people from outside your organisation, and leaves if one joins; an administrator can allow it. Each meeting gets a page in Claude with the notes, transcript and anything built. It is not offered to some organisations, such as those where Anthropic keeps no copy of chats (zero data retention). Meeting-note companies (Gong, Granola, Fireflies, Otter and others) are named as places transcripts can be sent, with no date. Where: Claude on web and desktop, Team and Enterprise plans.

The other reading

No independent hands-on report was found in the window. Everyone on a call must be fine with being transcribed; the post says so itself.

What to watch

Other video platforms are “coming soon”, without a date. Worth trying if you are on a Team plan and run internal calls on Google Meet.

Claude chatTRYTOP12 Nov
Opus 5.5 is now the default model on Pro, Max, Ultra and Team, and Anthropic says to leave it on
Anthropic recommends Opus 5.5 as the daily model for documents, research and spreadsheets, even for people who used the cheaper Sonnet. Its advice when an answer disappoints: raise the effort setting first, then change model.
●●●●● 5/5
The details

The comparison table gives prices per million tokens (tokens are the small pieces of text a model reads and writes): Anthropic’s four model sizes: Haiku 5.5 at $0.10 in and $0.50 out, Sonnet 5.5 at $2 and $10, Opus 5.5 at $4 and $20, Fable 5.2 at $8 and $40. Anthropic argues that a stronger model finishes with less work, which offsets part of the higher price. Higher-priced models use your plan limits faster. Fable 5.2 is not counted in the limits of Pro plans and standard Team seats outside limited-time offers, so it runs on usage credits. The test results are Anthropic’s own: in one internal research test, 16 of 18 reports passed a check that fails a report for a single invented figure. The models themselves belong to the Frontier Tech briefing.

What to watch

Watch your usage meter for a week; if it drains faster, drop to Sonnet 5.5 for well-scoped drafting.

CoworkTRY12 Nov
Windows: Claude no longer reopens blank, and Cowork tasks that went missing are back
The 12 November desktop update fixes a blank window after closing a minimised Claude, short freezes on opening a session, and Cowork tasks vanishing on Windows 11 after a switch to an earlier copy of the data.
●●●●● 5/5
The details

Also fixed: edits to an artifact (a document or page Claude builds beside the chat) being lost when you left within seconds of typing, and a lost Claude.ai sign-in on a company network that routes traffic through a gateway. Cowork task files now have a Download entry in their menu, so you can save a copy where you choose. Not stated: whether the missing tasks come back for people who already lost them, so open Cowork and check your task list after updating. Where: Claude desktop app on Windows, version of 12 November. What to do: update, restart, and look for your weekly briefing task.

CoworkWATCH12 Nov
Cowork tasks with limited internet access can no longer send code to GitHub or publish software packages
In tasks with restricted network access, Claude can download code from GitHub but not send changes back. Software-package sites still allow downloads, but publishing and sign-in there are refused. Tasks set to all domains are unaffected.
●●●●● 5/5
The details

The change is meant to stop a task from sending work out. A connected folder is also refused when its path runs through a shortcut (a link) that leads outside the folder; choose the real folder instead. Whether your briefing task counts as restricted depends on its Domain allowlist, the list of websites it may reach, in task settings. If you publish through GitHub from a task, look at that list before the next run. Not stated: whether Google Drive folders that appear as a shortcut on Windows count as such a link.

What to watch

If a publish step fails with a refusal on Monday, this is the first place to look.

Your stack: Claude Code 4 stories

Claude CodeTRYTOP13 Nov
Unattended runs can now stop and wait: terminal commands and scheduled skills ask for approval first
Three changes on 13 November make scheduled tasks more likely to pause at a prompt. Check your weekly briefing task before its next run.
●●●●● 5/5
The details

First, commands run inside Claude Code’s protective sandbox (a fenced area that limits what a command can touch) now ask first in the Manual and Accept edits permission modes, and Auto mode checks many of them; this is on macOS and Linux, and Windows is not named. To undo it, ask Claude Code to set autoAllowBashIfSandboxed to true in its settings. Second, scheduled tasks and /loop (a command that repeats a task) now ask before running a skill (a saved routine) that sets its own tool permissions or automatic actions, unless you allow that skill by name. Third, “Always allow” in the desktop app is offered only when saving it would really allow that command again, so a task that relied on one can now wait for you. Some saved approvals for terminal commands that set a variable such as NODE_ENV no longer match, so they ask again. Where: Claude Code 13 November and desktop app 13 November. What to do: open the task card and look for “Needs input”.

What to watch

A run that sits on a prompt looks like a run that did not start. Last week’s new status on the task card is how you tell.

Claude CodeTRY13 Nov
Update Claude Code: another batch of permission gaps was closed, plus a flaw in decoding compressed replies
The 13 November release closes several cases where a command could run without asking, or where a rule named one program and ran another. It also fixes a security issue in how compressed server replies are read.
●●●●● 5/5
The details

The notes list 195 fixes. The ones that touch your safety: some commands chained together now ask, an approval rule using a wildcard could run a different program than named, block rules missed some commands run with extra rights (sudo) or settings (env), and read-only git (code history) commands now ask in a project folder you have not marked as trusted. Also, an artifact that people outside your organisation can see now asks before every change, even under an allow rule. They name no outside report and no known misuse. Where: Claude Code, terminal and desktop Code tab. Updating is the whole action.

Claude CodeWATCH12 Nov
Long workflows in the Code tab now wait out a usage limit and carry on after the reset
In local sessions, a workflow that hits your plan’s usage limit pauses and continues when the limit resets, if that is within a day and Auto-continue when limits reset is switched on.
●●●●○ 4/5
The details

Until now a workflow stopped at the limit and waited for you. The setting is under the app’s options and, per the notes, must be on. Related: the number of messages one of your sessions can send to others without waiting was 10, then 20, and is now 100,000 on the 13 November release, effectively no cap. Not stated: how a paused run is shown on a phone. Worth it only if you run overnight jobs on a plan that you regularly exhaust.

What to watch

Switch it on the next time a long run is cut off by a limit.
